Bloomberg Invest: solution map
Filings in, cited facts out. Ten branches cover the whole system; the boards to the right detail the data flow, the graph schema, the endpoints and the code architecture.
Bloomberg Invest
Knowledge-graph analyst tool for companies listed on the Casablanca Stock Exchange
01 · SOURCES
Sources and inputs
· AMMC filings: annual and half-year reports, issuer pages
· Mostly French PDFs, kept under data/, never committed
· CLI metadata: ISIN, issuer, doc type, fiscal year
· Each PDF stored by its SHA-256 in data/documents/
· Golden set: Maroc Telecom 2025, 160 figures
· 12 golden test questions with their evidence
· Daily closing prices from the Bourse (planned)
02 · PIPELINE
Ingest pipeline
· Parse: Docling reads pages, sections, tables, cells
· Chunk: sections up to 2,000 tokens, tables 1,500
· Embed: Qwen3-Embedding-0.6B, run locally
· Extract: Azure OpenAI gpt-5.6-sol, page by page
· Check: Python keeps a figure only if it matches
· Every step records a Run with tool and config
· A failed step keeps the last good output
03 · GRAPH
Neo4j graph store
· Neo4j Community is the only store
· Filing: Document, Page, Section, Table, Cell
· Search: Chunk and the chunk_embedding index
· Figures: Fact, RejectedFigure, Span
· Provenance: Run, PRODUCED_BY, SUPERSEDED_BY
· Unique keys in Neo4j, types checked by Pydantic
· Old nodes are superseded, never deleted
04 · LANGUAGE
Domain terms
· Organisation, in roles: Issuer, Aggregate
· Listing: ticker, ISIN, sector, compartment
· Fact: one statement from one Passage, 9 kinds
· Conflict: same key, different values, both kept
· Period, As-of date, Basis (scope + standard)
· Line item (44 in label map v1) and its label
· KPI value, Screening, Price, Review, Run
05 · DECISIONS
Architecture decisions
· ADR 0001: one Fact per Passage
· ADR 0002: processing lives in the graph
· ADR 0003: Neo4j is the only store
· ADR 0004: Chunks are the search unit, by vector
· Vector beat hybrid: evidence@5 0.59 against 0.45
· Product spec in #19, decision map in #1
06 · API
FastAPI endpoints
GET /api/health
GET /api/documents · /api/documents/{id}
GET /api/documents/{id}/pages/{n}.png
GET /api/search?q=&limit=
GET /api/chunks/{id}
GET /api/companies/{isin} · …/figures
GET /api/facts/{id} OpenAPI: /api/docs
07 · WEB
React web app
· INDEX: every ingested filing
· Document: paper source viewer with highlights
· Company dossier: figures by basis, statement, year
· SEARCH: the Chunks nearest a question
· MAP, CHECKS, KPIs: placeholders for what is next
· Vite + TypeScript, client typed from OpenAPI
· nginx on :8080 proxies /api to FastAPI
08 · CODE
Code architecture
· Cosmic Python: entrypoints → service layer → domain
· Ports are Protocols: Parser, GraphStore, Embedder, LLM
· Adapters: Docling, Neo4j, Qwen3, Azure OpenAI
· bootstrap.py is the one place naming adapters
· views.py: the read models the API serves
· Versioned config: label map v1, prompt v1
09 · OPS
Run and test
· Docker Compose: neo4j, api, web
· Tools profile: ingest, chunk, embed, extract
· Tests: unit, integration (real Neo4j), e2e via API
· Markers: ingest, embed, live, golden
· LLM answers recorded once, replayed in tests
· CI: ruff, backend tests, notebooks stripped
· pipeline.ipynb to prototype a new step
