Endpoints and interfaces
Every way in: the HTTP API the web app reads, the CLI that writes, the web routes, and the services and settings that run them. The API only reads; all writes go through the CLI.
HTTP API · FastAPI
OpenAPI UI /api/docs · schema /api/openapi.json
MethodPathReturnsWhat it does
GET/api/health{status: "ok"}Health check used by Compose
GET/api/documentsDocumentSummary[]Every filing with a succeeded parse (the INDEX page)
GET/api/documents/{document_id}DocumentDetailOne filing: its pages, section tree and parse Run; 404 if unknown
GET/api/documents/{document_id}/pages/{number}.pngimage/pngA page rendered from the stored PDF, cached for a day; 404 past the last page
GET/api/search?q=…&limit=10Chunk[]The current Chunks nearest the query, best first; q 1 to 500 characters, limit 1 to 50
GET/api/chunks/{chunk_id}ChunkOne Chunk, current or not, so a result link survives a re-chunk
GET/api/companies/{isin}CompanyThe issuer and its filings (the dossier header)
GET/api/companies/{isin}/figuresFigureGridCurrent figures by basis, statement, line item and year, each with the Facts stating it
GET/api/facts/{fact_id}FigureDetailOne figure with its Passage, current or not, so links keep working after a re-run
CLI · bloomberg
ingest <pdf>
--issuer-isin --issuer-name
--doc-type --fiscal-year
[--source-url]		Parse, chunk, embed and extract a filing. Stops before parsing if the Azure OpenAI secrets are missing.
chunk <document id>Re-chunk from the saved parse, then embed the new Chunks
embed <document id>Re-embed the current Chunks
extract <document id>Re-extract the financial figures
In Docker: docker compose run --rm ingest | chunk | embed | extract …
